# 扫描页首次放大、分块和 PNG 优化验证

2026-10-13，`engine/pdfium`，实现提交 `463f004`、所有者缓存初始化修复 `e6adff8`。对照为 `main` / `engine/pdfjs` 的 `5e1efc4`，以及上一版 Canvas PDFium `2cdb6d5`。本轮保持一个主 Worker PDF 实例和完整原生回退。

405 MB 扫描图纸的三轮服务层中位数：首次放大 **699.4 → 156.1 ms**，四块合计 **62.3 → 37.8 ms**，PNG **1257.1 → 206.7 ms**，渲染流程峰值 PSS **2487.8 → 2380.5 MiB**。与 PDF.js 相比，首次放大和 PNG 明显更快；分块范围与 PDF.js 重叠，适合表述为接近，而不是每次都更快。书籍和复杂矢量页面继续使用原生路径，尚未全面超过 PDF.js。

## 最终实现

- 解码后的完整位图与阅读缩放层优先保留；释放 JPEG Blob 不再连带删除位图。临时缩放期间使用工作预算，完成绘制后再按驻留上限回收，避免中间层挤掉下一次缩放需要的源图。
- 默认驻留预算从 256 提高到 **512 MiB**，工作预算从 384 提高到 **640 MiB**，可容纳最近两张约 62 MP 的扫描源图，具体受其他缓存资源影响。阅读时优先保留当前完整源图和合适的缩放层。原生图像缓存仍以 256 MiB 为上限，并扣除 Canvas 占用；没有增加 PDF 实例。
- 分块和超过 8 MiB 的整页输出，在异步准备和取消检查完成后直接同步绘制到目标 Canvas，省去输出大小的中间位图。缩放层仍先物化为 ImageBitmap，避免小 Canvas 的绘制记录暗中保留大源图。
- PNG 复用已缓存的扫描正文，将不透明 RGBA 底图交给同一页的 PDFium 批注任务。原生批注因此能在真实背景上进行 Multiply 等混合。冷 PNG、复杂内容、蒙版、色彩配置或不支持的变换仍整页回退。
- AbortSignal 让取消请求立即结束等待。浏览器 `createImageBitmap` 的内部解码可能继续；其分配仍计入工作预算，迟到位图被关闭，不会写入画面或新缓存。替换文档后，旧所有者的内存通知不会覆盖新所有者的原生缓存预算。

这轮保持既有 JPEG 解码、逐级减半和全局像素对齐方式，没有通过降低输出分辨率换取速度。源码入口见 [扫描渲染器](../../packages/pdfium/src/scan.ts)、[原生背景 API](../../packages/pdfium/src/page.ts) 和 [Worker 集成](../../src/workers/pdf-render.worker.ts)。

## 画质与单实例

独立检查共 **127 个场景**：83 个 Canvas 路径、44 个原生回退。覆盖真实扫描、书籍、INDOT 图集，以及细字、细线、饱和色、裁剪、镜像、旋转、插值、蒙版、普通批注和 Multiply 透明组。另加入 8190×5460、约 44.7 MP 的合成 JPEG。

真实扫描正文相对 PDF.js：任一通道差超过 16 的像素比例最大 **0.000508%**，平均通道绝对误差最大 **0.1162 / 255**，继续满足 0.1% 和 0.5 的原有门槛。44 个回退场景与原生参考像素或 PNG 像素哈希完全一致。小图和新增大图的源分辨率输出均与原生 PDFium 完全一致。

饱和色 JPEG 沿用上一轮的色度差异门槛，并保留纯正文亮度检查：本轮合成正文最大严重 RGB 差异比例 **1.1992%**，最大平均通道误差 **0.5125**，最大亮度 RMSE **0.6628**，亮度差超过 16 的像素数为零。没有把这个 RGB 容差用于真实扫描。

**22 组分块重叠**检查最大通道误差为 14，最大平均误差为 0.008825，满足 16 和 0.05 的原有门槛。另目视检查了真实图纸的文字、细线分块和合成透明批注输出。

热缓存 PNG 的正文仍与 PDF.js 对照。真实 PNG 最大严重通道差比例为 **0.086336%**，平均误差最大 **0.0627**，通过同一严格 RGB 门槛。原生批注边缘与 PDF.js 的抗锯齿有既有差异，因此纯 JPEG 正文的亮度门槛不直接用于含批注 PNG；批注另与原生版本核对。

7 组 PNG 批注检查分别捕获正文和含批注输出。对于测试中的 Normal / Multiply，换背景引起的混合差异不能超过正文通道差异，加两级整数舍入余量。本轮批注作用像素数与原生版逐组相同，扣除正文差异后的**最大超额误差为 0**。SDK 另验证普通/旋转裁剪下，透明组和 Multiply 在不透明背景上的结果与原生整页输出逐字节相等。这不等于覆盖所有 PDF 混合模式。

本版 PDFium 的每个质量捕获点及最终计时会话均断言 `nativeDocuments = peakNativeDocuments = 1`，托管驻留/工作预算不超限。结束后 Worker 数为 0。完整捕获使用 `463f004`；`e6adff8` 只初始化新所有者的缓存预算，渲染器、原生背景 API 和 WASM 不变。最终三轮使用 `e6adff8`，扫描 PNG 像素哈希均与质量捕获一致。

证据：[像素比较](pdfium-scan-zoom/quality-comparisons.json)、[分块重叠](pdfium-scan-zoom/quality-seams.json)、[批注检查](pdfium-scan-zoom/quality-annotations.json)、[捕获记录](pdfium-scan-zoom/quality-renders.json)。私人 PDF 和截图不进入仓库。

## 同条件服务层比较

Linux ARM64，4 核 Cortex-A76，约 8 GiB RAM，Chromium 148.0.7778.167，软件 Canvas/光栅化。三轮轮换版本顺序，每次启动独立浏览器；计时期间没有并行构建、测试或图像验证。27 / 27 会话完成，无失败。

三份固定文件为 288 页书籍、1000 页公开 INDOT 图集和 43 页扫描图纸。共同流程是打开、1600 px 首帧、模型解析、三个抽样页的冷/热绘制、已访问页首次放大到 3200 px、重复绘制、6400 px 页面下的四个 1024² 分块、旋转分块和 1600 px PNG。这里的“首次放大”是在先前看过该页 1600 px 输出后进行，不是从未访问过的页面。

时间包含 Worker RPC 和动画帧确认，单位 ms，不是物理屏幕扫描输出延迟。每轮三个抽样页先取中位数，再取三轮中位数。原始数据及范围见 [结果](pdfium-scan-zoom/results.json) 和 [汇总](pdfium-scan-zoom/summary.json)。

首次放大的三轮范围：PDF.js 436.7–472.7 ms，上一版 693.9–718.3 ms，本版 155.0–158.5 ms。四块合计范围分别为 37.0–51.7、58.1–63.0、36.4–38.1 ms。服务层打开＋首帧本版比上一版略慢，实际界面首帧则更快，不能把两个测量入口互换。

本轮使用 `PDF_BENCH_RENDER_ONLY=1`，内存覆盖上述渲染/PNG 流程，**不包括完整 PDF 合并保存或下载峰值**。PSS 每 50 ms 汇总 Chromium 进程树，可能漏掉更短尖峰；驻留值在主线程和 Worker GC 后记录。输入及 donor 字节在基线前已预载。WASM 容量不等于实际驻留内存。

缓存加大有明确代价：首帧可读后的驻留 PSS 增加约 241 MiB；后续缩放减少重复解码，流程结束驻留和峰值中位数降低。三轮峰值范围：上一版 2453.0–2491.5 MiB，本版 2333.3–2485.0 MiB，存在重叠。实际界面测量结束时的 PSS 也由 2302.3 增至 2362.6 MiB。不能把这次变化描述为所有阶段都更省内存，或把 512 / 640 MiB 视为浏览器总内存上限。

六个独立调度会话通过：前台均先于后台预览完成；取消恰好回复一次 `false`；立即重新渲染成功；元数据保存保留扫描缓存并能重绘。

| 调度任务（三轮中位数，ms） | 上一版 PDFium | 本版 PDFium |
| -------------------------- | ------------: | ----------: |
| 后台预览期间的前台请求     |          39.6 |        20.9 |
| 取消到回复                 |         696.5 |         8.5 |
| 元数据保存后重绘           |          36.0 |        12.1 |

取消数值是回复延迟，浏览器内部 JPEG 解码可能尚未结束；迟到结果会关闭并释放保留的预算。SDK 测试同时验证了取消后的分配仍被计费，工作空间不足时新任务不会再启动一次完整解码。调度记录见 [preemption.json](pdfium-scan-zoom/preemption.json)。

新旧版均完成离线 PWA 的导入、表单修改、插入空白页、撤销/重做及保存复开：8 页、3 个表单字段，`name = Bob`，主 Worker 从 1 变为关闭后的 0，无可见破图。两版都出现一次已撤销 Blob 缩略图 URL 的 `ERR_FILE_NOT_FOUND`，本轮未修复这个既有竞态，也没有把它隐去。证据：[本版 PWA](pdfium-scan-zoom/pwa.json)、[上一版 PWA](pdfium-scan-zoom/pwa-before.json)。

SDK 49 项测试、应用 787 项测试、ESLint/TypeScript、原生 WASM 编译、Web 和 Tauri 前端构建通过。Tauri 原生应用/GPU 渲染、其他浏览器、更多混合模式和完整大文件导入保存的峰值，均不属于本轮已测性能结论。

## 复现与来源

构建和运行入口见 [benchmark README](../../scripts/pdf-benchmark/README.md)。[manifest.json](pdfium-scan-zoom/manifest.json) 保存版本和文件位置，[provenance.json](pdfium-scan-zoom/provenance.json) 保存源文件、构建产物及 PDF 的 SHA-256，[validation.json](pdfium-scan-zoom/validation.json) 保存检查结果。旧版质量参考来自上一轮相同不可变源码版本，新增 PNG 参考使用支持字节捕获的共同入口重新生成。

```sh
bun run --cwd packages/pdfium build
node scripts/pdf-benchmark/build.mjs /path/to/checkout /tmp/corpus corpus-entry.ts
node scripts/pdf-benchmark/scan-validate.mjs /tmp/quality-manifest.json /tmp/quality
PDF_BENCH_RENDER_ONLY=1 node scripts/pdf-benchmark/corpus.mjs /tmp/manifest.json /tmp/results 3
node scripts/pdf-benchmark/corpus-summary.mjs /tmp/results/results.json /tmp/results/summary.json
node scripts/pdf-benchmark/reader-ui.mjs /tmp/before-app /tmp/after-app /path/to/scan.pdf /path/to/book.pdf /tmp/ui.json 3 /tmp/pdfjs-app
node scripts/pdf-benchmark/preemption.mjs /tmp/before-app /tmp/after-app /path/to/scan.pdf /tmp/preemption.json 3
```

Playwright / pngjs 仅用于人工基准工具；按本机安装位置设置 `NODE_PATH`。质量、计时和实际界面分开运行。公开 INDOT 来源为清单中的官方链接，私人图纸沿用之前获授权的本机样本，不对外发布。
